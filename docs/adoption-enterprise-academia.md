# 企业与高校落地方案(Adoption Guide)

> 面向: 正在评估或启动 HumanValue 落地的企业 HR/IT 与高校人事处/信息化办。
> 目标: 用最小试点成本验证价值,再分阶段扩展到全员。
> 配套阅读: [试点 Runbook](pilot-runbook.md) · [员工权利与算法合规](compliance-employee-rights.md)

## 1. 两类主场景画像

### 1.1 企业场景

| 要素 | 典型配置 |
|---|---|
| 决策者 | BOSS(老板视角看板) / CHO |
| 使用者 | HRBP、直线经理、员工自助 |
| 核心诉求 | 关键人才盘点、继任梯队、薪酬竞争力、倦怠预警、PIP 全流程留痕 |
| 体系类型 | `TALENT_SYSTEM_TYPE=enterprise_elimination`(默认) |
| 数据敏感点 | 薪酬数据、绩效原始输入——必须字段加密+审计 |

**切入点建议**: 从"季度人才盘点"切入(九宫格 + 继任管线),先让 BOSS/HR 看板跑起来,
再开放经理端审批流,最后放开员工自助。避免一上来就全功能铺开。

### 1.2 高校场景

| 要素 | 典型配置 |
|---|---|
| 决策者 | 人事处 / 院系负责人 |
| 使用者 | 教师发展中心、二级学院秘书、教师本人 |
| 核心诉求 | 教师队伍结构分析、青年教师帮扶分流、考核周期管理 |
| 体系类型 | `TALENT_SYSTEM_TYPE=academic_cultivation` |
| 数据敏感点 | 师德师风类记录单独权限;评估结论避免直接挂钩职称"一票否决" |

**切入点建议**: 从"队伍结构诊断报告"切入(纯只读分析,无个人处置动作),
建立信任后再启用培养计划跟踪。

## 2. 角色与功能映射

| 角色 | 平台入口 | 高频操作 |
|---|---|---|
| BOSS | TalentValueDashboard / TeamROI | 看人才大盘、ROI、单点故障风险 |
| HR | HRDashboard / HRAuditDetail | 评估复核、审计追溯、批量导入 |
| 经理 | ManagerDashboard / ApprovalDetail / CalibrationView | 团队评估审批、校准会、离职风险 |
| 员工 | EmployeeDashboard / GrowthPath / Feedback | 自助录入、成长路径、反馈 |

RBAC 保证越权不可见(如经理只能看直属下属);ABAC 支持更细粒度的部门/租户隔离。

## 3. 分阶段落地路线

| 阶段 | 时长 | 内容 | 退出标准 |
|---|---|---|---|
| P0 环境 | 1 周 | docker compose 生产栈(PostgreSQL+Redis+MinIO+Grafana);SSO 对接;合规告知发放 | check_prod_readiness 通过;试点名单账号开通 |
| P1 只读试点 | 2-4 周 | 导入组织架构与历史考核;仅 BOSS/HR 使用分析看板;不开处置动作 | 报告被决策层采信;数据质量抽检通过 |
| P2 审批闭环 | 4-8 周 | 开放经理端评估草拟→审批流;开启公平性月检 | 审批采纳率、申诉率有基线数据 |
| P3 全员自助 | 8 周+ | 员工端开放;接入飞书/GitLab 等集成;DR 备份演练 | 月活与自助率达标;RTO/RPO 演练通过 |

## 4. 集成清单

- **SSO/OIDC**: `/api/v1/admin/sso/configs` 配置;LDAP 走 SSO API(需 ldap3)
- **IM 通知**: 飞书/Lark(`FEISHU_APP_ID/SECRET`),未配置自动降级 Dummy 适配器
- **代码仓联动**(研发团队): GitLab(`GITLAB_BASE_URL/TOKEN`)用于工程师能力证据采集
- **本地大模型**: `LOCAL_BASE_URL` 指向内网 Ollama/Xinference,`MODEL_TIER=L2/L3`,
  实现"评分数据不出域";云模型走 `CLOUD_*` 且凭据 AES 加密存储

## 5. 成功指标(Suggested KPI)

| 维度 | 指标 | 参考目标(P2 结束时) |
|---|---|---|
| 采纳 | 经理周活跃审批数 / 应审批数 | ≥ 60% |
| 质量 | AI 结论人工修正率 | ≤ 30% 且逐月下降 |
| 公平 | fairness_audit 群体偏差指标 | 无显著劣势群体(p<0.05) |
| 合规 | 告知书签署率 / 申诉按时响应率 | 100% / ≥ 95% |
| 稳定 | 评估流水线成功率 | ≥ 99% |

## 6. 常见落地坑

1. 直接全功能上线 → 员工恐慌。按 §3 阶段走,先只读后动作。
2. 跳过公平性基线 → 出现群体偏差争议时无法自证。P1 就要跑第一次。
3. 用默认演示密码/占位密钥上生产 → `check_prod_readiness` 会拦截,但别依赖兜底。
4. 把平台当考勤/监控工具用 → 定位是"人才价值盘点",监控类需求请用专业系统。
