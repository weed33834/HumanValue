# 员工权利与算法合规指南

> 适用对象: 部署 HumanValue 的企业与高校的 HR/法务/IT 负责人。
> 本文档说明平台在"AI 参与人才评估"场景下的合规设计、部署方义务与建议配置。
> 本文档为工程合规指引,不构成法律意见;正式部署前请结合属地法规咨询法务。

## 1. 为什么这是生死线

HumanValue 的核心能力是**对"人"打分**: AI 生成九宫格定位、绩效评估、PIP(绩效改进)、
淘汰建议等。这类自动化决策在主要法域均受严格约束:

| 法域 | 关键条款 | 对平台的要求 |
|---|---|---|
| 中国《个人信息保护法》 | 第 24 条 自动化决策 | 透明度+结果公平公正;不得只在自动化决策方式上搞不合理差别待遇;可拒绝仅通过自动化决策作出的决定;有权要求说明 |
| 欧盟 GDPR | 第 22 条 自动化个人决策 | 数据主体有权不受完全自动化决策约束;要求数据控制者提供人工干预途径、表达立场、提出异议 |
| 欧盟 AI Act | 就业类属高风险系统 | 人类监督、日志留存、透明度义务、风险评估 |

**结论: 平台必须以"辅助决策"而非"替代决策"的姿态落地。**

## 2. 平台内置的合规能力(已实现)

| 能力 | 位置/配置 | 说明 |
|---|---|---|
| 审批流(人工复核) | `services/approval_service.py` | AI 草拟 → 经理审批才生效,天然的人工介入点 |
| RBAC + ABAC 权限 | `auth/rbac.py` / `auth/abac.py` | BOSS/HR/经理/员工分级可见,员工数据非全员可见 |
| 敏感字段加密 | `FIELD_ENCRYPTION_KEY` (AES-GCM) | manager_view/audit_view 字段级加密,生产必须配置 |
| 数据保留策略 | `RETENTION_RAW_INPUT_DAYS=730` 等 | 原始输入/评估结果到期清理,含缓冲期 |
| 审计日志 | `audit_service` + append-only 触发器 | 谁在何时看了/改了什么,不可篡改 |
| 公平性审计 | `scripts/fairness_audit.py` | 按群体维度检测评分偏差,支持月度运行 |
| GDPR 审计 | `scripts/gdpr_audit.py` | 数据主体权利响应(查询/导出/删除)核查 |
| 登录风控 + MFA | `LOGIN_LOCK_*` / `MFA_*` | 防暴力破解,管理员可强制双因子 |
| PII 红action | `core/utils/pii.py` + 输入护栏 | 日志与审计中的个人信息脱敏 |

## 3. 部署方义务清单(Go-Live 前)

- [ ] **告知义务**: 向被评估员工书面说明"AI 参与评估的范围、用途、依据与申诉渠道",取得知情同意
- [ ] **人工复核闭环**: 明确每个 AI 结论(尤其 PIP/淘汰类)必须经人工审批生效——审批流默认开启,勿关闭
- [ ] **拒绝权通道**: 提供员工对纯自动化结论说"不"的渠道(线下申诉表单或工单),并在制度中写明时限
- [ ] **最小化采集**: 关闭试点不需要的数据管道;原始输入保留期按需调短(`RETENTION_RAW_INPUT_DAYS`)
- [ ] **加密落地**: 生产环境设置强随机 `JWT_SECRET_KEY` 与 `FIELD_ENCRYPTION_KEY`(check_prod_readiness 会拦截占位值)
- [ ] **公平性基线**: 上线前跑一次 `python -m scripts.fairness_audit`,此后纳入月度例会
- [ ] **审计留痕**: 确认审计日志外发/备份策略满足当地留存年限要求
- [ ] **模型透明度**: 在管理后台登记所用 LLM 供应商与版本,供问询时出具

## 4. 企业 vs 高校的差异要点

| 维度 | 企业(elimination 制) | 高校(cultivation 制) |
|---|---|---|
| 处置框架 | PIP/汰换/激励 | 帮扶/分流/成长,慎用淘汰语义 |
| 法规侧重 | PIPL 第24条 + 劳动法证据链 | 教师法/事业单位人事条例 + 学术评价规范 |
| 建议配置 | `TALENT_SYSTEM_TYPE=enterprise_elimination` | `TALENT_SYSTEM_TYPE=academic_cultivation` |
| 特别提示 | 淘汰相关报告须有完整人工审批记录,作为劳动争议证据链 | 评分结果避免直接关联职称评审一票否决 |

## 5. 反模式(禁止)

- 把 AI 评分直接作为唯一裁员/辞退依据而不经任何人工实质审查
- 对员工隐藏"系统参与评估"这一事实
- 关闭审批流让 AI 结论直达执行层
- 用同一模型对不同群体做无差别阈值切割而不做公平性校验
- 在测试环境之外长期开启 demo 认证(`AUTH_DEMO_MODE`)

## 6. 快速自检命令

```bash
# 生产就绪守护(占位密钥/演示模式会被拦截)
cd backend && python -m scripts.check_prod_readiness

# 公平性与 GDPR 自检
python -m scripts.fairness_audit
python -m scripts.gdpr_audit
```
